{% extends base_template %} {% comment %} RFP §5.1 — the teacher's entry form, redesigned 2026-08-16 (docs/UI_AUDIT.md). This is the screen a teacher opens most often, and it was one flat stack of eighteen controls: date through to the report checkbox, every label the same weight, layout held together by inline styles. Nothing was wrong with it and nothing about it said what to do next. Five sections now, in the order the thought actually runs — when and what kind, what happened, what the teacher makes of it, who may see it, and the photograph. The fields, their names and their validation are untouched: the view still parses `request.POST` itself (`_posted`), so every input here keeps the exact name that function reads. Sections are headings and whitespace, not cards. Five bordered rectangles down a phone screen would make a long form feel longer, and the dashboard next door already settled that question. **Media is section five and is deliberately not an upload input.** `media:observation_attach` takes an `observation_id`, so on a new form there is nothing to attach to yet. The section says so and offers the action once the record exists, rather than showing a control that cannot work — spec section 7.1 owns that pipeline and this screen does not duplicate it. {% endcomment %} {% block title %}{% if observation %}Ажиглалт засах{% else %}Шинэ ажиглалт{% endif %}{% endblock %} {% block heading %}{% if observation %}Ажиглалт засах{% else %}Шинэ ажиглалт{% endif %}{% endblock %} {% block lede %}
